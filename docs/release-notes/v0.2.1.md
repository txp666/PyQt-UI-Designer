本版本让 Modbus 卡片像组态软件那样自动轮询：只要在控件上绑定寄存器，卡片自己决定发哪些读请求、什么时候发；写命令和读请求在同一条链路上排队，一次只有一个请求在线上。`.uidp` 工程与 FluentHMI Studio 0.2.1 互通。

- Modbus 自动轮询：Modbus 卡片新增「轮询方式」（`pollMode`，默认"自动"）和「连接后自动轮询」（`autoStart`，默认开）。自动方式下不用写轮询表，卡片按控件的 Modbus 绑定和实时曲线的 Modbus 曲线规划读取：同一从站、同一功能码里相近的地址合并成一块（寄存器间隔 ≤ 8、一块 ≤ 120 个，线圈和离散输入间隔 ≤ 64、一块 ≤ 1000 个），每块按绑定新增的「采集周期(ms)」（`mbPeriod`，0 用卡片的轮询 ms）读取，只读界面上看得见的控件，选项卡其他页上的不读。每条链路有一个 Modbus 主站队列，一次只有一个请求在线上，写命令排在读请求前面，轮询中按按钮写入不会再和在途的读请求撞车。状态栏显示"自动 · N 块 · 正常"、无响应或返回异常的块，鼠标悬停列出各块的从站、功能码、地址和周期。规划规则与 FluentHMI Studio 用同一份向量文件（`tests/data/poll_plan_vectors.json`）测试。
- 设计器：Modbus 卡片的「轮询表」只在轮询方式为「轮询表」时显示，标题下一行小字显示当前轮询方式；Modbus 绑定的最后一行是「采集周期(ms)」。`check_uidp.py` 校验 `pollMode`、`autoStart` 和 `mbPeriod`。
- 文档：`docs/protocol.md` 的 Modbus 卡片一节改写为「自动轮询」为主、「轮询表」为高级用法；`docs/uidp-format.md`、`docs/uidp-widgets.md` 同步。
- 导出的程序运行时代码同步更新（`serial_handler.py` 里新增每条链路的 Modbus 请求队列，`tcp_handler.py`、`mqtt_handler.py`、`ui.py`、`data_binding.py` 随之更新），独立 demo 已重新生成。运行依赖没有变化。

`.uidp` 文件向后兼容：没有 `pollMode` 的旧卡片（有没有轮询表都一样）按"轮询表"方式打开，也不会连上就自动开始，和以前一样点「轮询」才开始，状态文字与之前相同；示例 `examples/tutorials/` 未改动。设计器里新放的 Modbus 卡片默认是自动方式、连接后自动轮询。
