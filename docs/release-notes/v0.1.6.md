本版本新增 TCP 和 MQTT 通信，并支持 Modbus TCP。串口、TCP、MQTT 共用同一套解析、数据绑定和命令发送，设计器预览和导出的程序行为一致。

- 新增 TCP 配置卡片：客户端模式连接设备的 IP 和端口，服务端模式监听端口等待设备连入。服务端可同时接多个设备，每个连接单独切帧，命令发给所有已连接的设备。
- 新增 MQTT 配置卡片：连接 broker，订阅一个或多个主题（支持 `+`、`#` 通配符），命令发布到指定主题；支持用户名密码、QoS 0/1/2 和 TLS。每条消息按一帧解析，没有换行结尾也能解析；只有一个数值的消息可以直接用主题名绑定。连接意外断开后自动重连并恢复订阅。
- 新增 Modbus TCP 解析模式 `modbus_tcp`：按 MBAP 头切帧，解析结果和 Modbus RTU 相同，原有 Modbus 绑定不用改。按钮、开关、滑块和 Modbus 卡片发送 Modbus 命令时，按每条链路的解析模式自动选择 MBAP 帧或带 CRC 的 RTU 帧。
- 多条链路可以同时连接：收到的数据进入同一套绑定、曲线、表格和日志，命令发往每一条已连接的链路。
- TCP 和 MQTT 卡片在"连接中"和"重连中"时可以点"断开"取消。连接失败的原因显示在卡片状态中，如连接被拒绝、用户名或密码错误。
- 修复 macOS 安装包点"检查更新"提示证书校验失败（`CERTIFICATE_VERIFY_FAILED`）的问题：安装包内置的 OpenSSL 找不到证书文件。检查更新和 MQTT 的 TLS 连接改为通过系统证书库（macOS 钥匙串、Windows 证书存储）校验服务器，导出的程序同样如此；自签证书需要加入系统信任。
- 日志框的连接提示改为"已连接 / 已断开"，不再固定写"串口"。
- 设计器退出时，先在 Qt 应用对象仍存在时销毁设计画布及其中的控件，不再交给 Python 退出流程按不确定的顺序清理，避免偶发的退出崩溃。
- 导出的程序新增 `comm_hub.py`、`tcp_handler.py`、`mqtt_handler.py`，运行依赖新增 `paho-mqtt` 和 `truststore`。同步更新独立 demo 的导出代码。

提供 Windows x64、macOS Apple Silicon（arm64）、macOS Intel（x64）独立运行包及 SHA-256 校验文件。解压后运行 `main.exe` 或 `.app`，无需安装 Python。

Mac 安装包未做 Apple Developer ID 签名与公证；Windows 安装包未做 Authenticode 签名。TCP 使用本机回环连接验证，MQTT 使用本地 broker 验证（含断线重连和 TLS），Modbus TCP 使用模拟设备验证；实际硬件和云平台仍需按设备协议联调。
