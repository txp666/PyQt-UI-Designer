# Classic S7comm

S7 is available in the designer preview, exported Python source and Nuitka applications. Add an **S7 configuration card**, then select **S7** as a widget's binding or command mode. Select the connection card explicitly: S7 traffic has its own typed route and is never broadcast to the serial, TCP, UDP or MQTT links.

This backend targets S7-300/400 and absolute PUT/GET access to S7-1200/1500 with PUT/GET enabled and non-optimized DBs. S7CommPlus, symbolic/optimized DB access, RUN/STOP and program downloads are outside its scope. The PLC's protection settings must permit the requested access.

## Build the native dependency

The project uses the official [Snap7](https://github.com/davenardella/snap7) C ABI through a small `ctypes` adapter, pinned to commit `30f37da3114024a71ba93f7fd855c680b97a406f` (1.4.3). It does **not** install or import `python-snap7`: 2.x wrappers and the pure Python 3.x package have different APIs and behavior.

Install a C++ compiler, CMake 3.21+ and Ninja for your platform (Visual Studio C++ Build Tools on Windows, Xcode Command Line Tools on macOS). From the repository root:

```sh
git submodule update --init --recursive
python -m pip install cmake ninja
python scripts/build_snap7.py
```

On Windows run the build from a Visual Studio developer terminal. Build with the same architecture as Python: arm64 Python on Apple Silicon, x64 Python on Intel/Windows. The script checks the exact submodule commit and builds `snap7.dll`, `libsnap7.dylib` or `libsnap7.so` into `app/resource/native`. It applies `patches/snap7-macos.patch` on macOS and `patches/snap7-connect-timeout.patch` on every platform to a build copy; the submodule stays unmodified. The patches fix macOS monotonic timing/SIGPIPE and bounded TCP connection establishment.

Snap7 is **LGPL-3.0-or-later**; this application remains **GPL-3.0**. Exported S7 projects include the platform's dynamic library, both upstream license texts and `native/SOURCE.txt`. Keep these with redistributed applications. The library remains a separate, replaceable dynamic dependency; its pinned source, patches and build instructions are available in this repository. Nuitka collects it as a DLL with dependency analysis/signing, rather than as an ordinary data file. Windows/macOS CI builds from the same pinned source; a local macOS check does not establish that Windows has been tested.

## Connection and point settings

The card's `id` is its connection ID. Its `properties` defaults are:

```json
{
  "host": "127.0.0.1", "port": 102, "rack": 0, "slot": 1,
  "connectionType": 1, "period": 500, "timeout": 1000,
  "autoConnect": false, "autoReconnect": true, "reconnectInterval": 1000
}
```

`host` is an IPv4 address. Rack is 0–7, slot 0–31; connection type is 1=PG, 2=OP, 3=S7 Basic. Poll, timeout and reconnect intervals are milliseconds, 1–60000. The running card exposes the basic connection fields; the designer property panel also edits the polling, timeout and automatic connection settings.

Addresses are absolute and normalized without changing their meaning:

| Type | Example addresses | Encoding |
| --- | --- | --- |
| BOOL | `DB1.DBX0.0`, `M0.0`, `I0.1`, `Q0.0` | One bit |
| BYTE / SINT | `DB1.DBB1`, `MB1`, `IB1`, `QB1` | Unsigned / signed 8-bit |
| WORD / INT | `DB1.DBW2`, `MW2`, `IW2`, `QW2` | Unsigned / signed 16-bit, big-endian |
| DWORD / DINT | `DB1.DBD8`, `MD8`, `ID8`, `QD8` | Unsigned / signed 32-bit, big-endian |
| REAL | `DB1.DBD16`, `MD16`, `ID16`, `QD16` | Finite IEEE float32, big-endian |

Address width must match the type. DB numbers are 1–65535, bit numbers 0–7. Case and leading zeros normalize; `MX0.0` normalizes to `M0.0`. Integer text is decimal (`-1234`); fractional/scientific integer strings, hexadecimal strings, overflow and NaN/Infinity are rejected. BOOL accepts true/false or 0/1. BOOL writes use native `S7WLBit`, preserving neighboring bits without a byte read/modify/write operation.

Binding example:

```json
{"parseMode":"S7","sourceCardId":"plc-main",
 "s7":{"address":"DB1.DBD16","dataType":"REAL","period":0}}
```

Point `period:0` follows the connection default. Chart curves use `_curve_0_parseMode:"S7"`, `_curve_0_sourceCardId` and `_curve_0_s7` with the same point object. Commands use `properties.commandMode:"S7"`, `commandTargetId` and:

```json
{"s7Command":{"address":"DB1.DBX0.0","dataType":"BOOL",
              "value":"1","onValue":"1","offValue":"0"}}
```

Buttons send `value`; switches send the nested `onValue`/`offValue` (separate from the switch's receive condition). Line edits send their entered text, sliders/spin boxes their current value, and combo boxes their existing command-table value or selected text. PLC feedback updates controls with signals blocked, so polling never sends the displayed value back. An editable focused line edit retains the user's in-progress text.

Each connection has one serialized background I/O worker. Typed samples include the connection ID, canonical address, type, value, quality, timestamp and session generation. Bad/disconnected samples do not replace readings with zero. Reconnecting starts a new generation and drops stale results. A failed or timed-out write is not retried, and queued writes are discarded on disconnect; an unconfirmed write is reported rather than presented as successful. Closing preview requests worker shutdown without blocking the GUI; the native connect/send/receive operations have bounded timeouts.

Projects with an active S7 card, binding, curve or command save as UIDP **1.1** and require an S7-capable designer. New desktop versions read 1.0 and 1.1; projects without S7 continue to save as 1.0. The browser editor does not implement this S7 backend.

## Try the simulator

Open [`examples/s7/classic-s7.uidp`](../examples/s7/classic-s7.uidp). Both cards start disconnected. Start two independent [FluentPLC Simulator](https://github.com/txp666/FluentPLC-Simulator) servers with the supplied project files:

```sh
FluentPLCServer --project examples/s7/plc-main.plcsim.json --listen 127.0.0.1 --port 1102
FluentPLCServer --project examples/s7/plc-other.plcsim.json --listen 127.0.0.1 --port 1103
```

Connect the cards in preview. REAL temperature, INT speed, DWORD count and the dynamic sine chart are read from their selected PLC. The switch writes `DB1.DBX0.0`; bit 7 of that byte remains set. The button writes only to the second PLC, while line edit/slider/spin/combo write the first PLC. Export source, install its generated `requirements.txt` and run `main.py`; its `native` folder must stay beside the generated files. One-click Nuitka packaging includes that dependency automatically. Exported libraries are platform-specific: export/build on each target OS and architecture.

中文快速步骤：先构建 Snap7 原生库，打开示例工程，在「预览」中连接 1102/1103。新增控件时，在「数据绑定 → S7」选择连接、绝对地址和类型；写入在「发送模式 → S7」中单独指定目标卡片。高级连接参数在设计器属性面板编辑。S7 工程使用 UIDP 1.1，须使用新版桌面设计器；网页版不支持 S7。

## Regression checks

```sh
python -m unittest tests.test_s7 -v
python -m unittest discover -s tests -q
python tools/check_uidp.py examples/s7/classic-s7.uidp
python tools/check_i18n.py
```

Local validation on macOS arm64 / Python 3.14.6 covered the native library, all eight types and DB/M/I/Q areas, independent PLC connections, bit writes preserving neighbors, preview/source-export control feedback, chart polling and targeted user writes. An independent pure Python protocol client cross-checked the simulator memory. A loopback endpoint that accepted TCP but never answered S7 negotiation confirmed that a 200ms timeout let the worker exit in about 0.20s while Qt continued processing timer events. These are local simulator checks, not a physical Siemens PLC or Windows validation.

The final standalone source was also compiled with the standard Nuitka build helper and archived with `archive_build` as a macOS `.app`, ZIP and SHA-256 file. The actual packaged app loaded `Contents/MacOS/native/libsnap7.dylib` from its own bundle and displayed both PLCs' REAL/INT/DWORD readings and live chart. Independent wire reads verified switch writes preserving the neighboring bit, a line-edit write and a button write targeted only to the second PLC. Local build artifacts are under `dist/s7-local`; binaries are not committed.
